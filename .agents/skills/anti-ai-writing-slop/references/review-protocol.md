# Review protocol

Run this process on the current draft or output.

## 1. Establish the contract

Write down, briefly:

- audience and channel
- intended action or takeaway
- facts that must survive the edit
- voice evidence available
- explicit bans or formatting rules

Treat supplied voice samples as evidence, not text to imitate word for word. If no custom profile exists, use the starter profile in `voice-profile.md` and state that assumption.

## 2. Run blocking checks

Reject the draft when it contains:

- an unsupported factual claim, metric, quote, testimonial, or promise
- a contradiction with the source material
- private or identifying context that should not be public
- a phrase or construction marked **Block** in `banned-patterns.md`
- a violation marked **Block** in the active voice or project rules

Stop and report a blocking issue before polishing the rest when it could make the copy misleading or unsafe.

## 3. Run material checks

Check whether the draft:

- answers the request instead of an adjacent version
- starts near the point
- uses concrete nouns and verbs
- separates evidence from inference
- varies sentence and paragraph length naturally
- keeps useful uncertainty where certainty is not earned
- sounds consistent with the available samples
- removes repetition, throat-clearing, and empty transitions
- ends with a practical action, implication, or boundary when the format needs one

## 4. Rate

- **Needs work:** At least 1 blocking issue, or several material issues.
- **Good:** Accurate and usable, with a small number of material edits still worth making.
- **Ready:** Accurate, specific, voice-consistent, and publishable without another style pass.

## 5. Revise and recheck

Revise only what improves accuracy, clarity, rhythm, or voice match. Protect lines that are slightly loose but clear and distinctive.

Re-run the checks after editing. Stop when the result is **Ready** or after 3 rounds. If it still is not ready, name the unresolved constraint instead of pretending the style pass solved it.

## Finding format

For every blocking or material finding, provide:

1. the exact phrase
2. the violated rule
3. why it matters for this audience
4. the smallest useful fix

Avoid vague notes such as "the tone is off."
